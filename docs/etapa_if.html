Etapa IF

Instruction Fetch: busca la instrucción que apunta el PC y la deja en el latch IF/ID junto con su dirección. El latch está repartido: pc, pc4 y valid son registros propios, y la instrucción es el registro interno de salida de la BRAM.

Qué pasa en cada flanco

En el flanco de subida del clock, si no hay stall, salto ni halt, pasan tres cosas al mismo tiempo:

IF/ID.pc    <= PC              // registro propio
IF/ID.instr <= mem[PC[11:2]]    // registro de salida de la BRAM (lectura sincronica)
PC          <= PC + 4          // o branch_target si branch_taken = 1

Las tres usan el valor de PC de antes del flanco. Por eso el par (IF/ID.pc, IF/ID.instr) siempre corresponde a la misma instrucción, aunque el PC ya haya avanzado.

Del diagrama al Verilog

Mux, sumador y enable de la BRAM

wire [31:0] pc_plus4 = pc + 32'd4;
wire [31:0] next_pc  = branch_taken
                       ? branch_target
                       : pc_plus4;
wire bram_en = en & (branch_taken | ~stall);

BRAM y mux de NOP

instr_mem imem (
  .clka(clk), .ena(bram_en), .wea(1'b0),
  .addra(pc[11:2]), .douta(bram_dout),
  .clkb(clk), .web(dbg_we), .addrb(dbg_addr),
  .dinb(dbg_wdata), .doutb(dbg_rdata));

assign if_id_instr = if_id_valid
                     ? bram_dout : `INSTR_NOP;
always @(posedge clk) begin
  if (reset) begin
    pc <= 0; if_id_pc <= 0; if_id_pc4 <= 0; if_id_valid <= 0;
  end else if (en) begin
    if (branch_taken) begin   pc <= next_pc; if_id_valid <= 0;            // flush
    end else if (stall) begin                                          // todo quieto
    end else if (halt) begin  if_id_valid <= 0;                         // entran NOPs
    end else begin            pc <= next_pc; if_id_pc <= pc;
                              if_id_pc4 <= pc_plus4; if_id_valid <= 1;
    end
  end
end

Para la defensa

  1. ¿Por qué la salida de la BRAM forma parte del latch IF/ID?La BRAM lee de forma sincrónica: el dato sale en el mismo flanco en que IF/ID guarda el PC. Su registro de salida ya cumple la función del campo instr, así que agregar otro registro solo sumaría un ciclo de latencia.
  2. ¿Qué pasa con la BRAM durante un stall?Su enable (ena) baja a 0, ignora el flanco y conserva la misma instrucción a la salida. Así se congela sin tocar el clock.
  3. ¿Por qué el PC avanza de a 4 y la BRAM recibe PC[11:2]?El PC cuenta bytes y cada instrucción mide 4. La BRAM cuenta palabras: se descartan los 2 bits bajos (dividir por 4) y se toman 10 bits porque 2¹⁰ = 1024 palabras.
  4. ¿Qué pasa si el programa no tiene HALT?El PC sigue avanzando sobre lo que haya en memoria. Al pasar 0xFFC, PC[11:2] vuelve a 0 y el programa empieza de nuevo, sin terminar nunca. Lo prueba el último caso del testbench.
